# 虚构招聘演示素材

包含 20 个岗位 JD、24 份虚构简历，按每岗 4 人分配，共 80 条候选人记录。
所有岗位名称带 `[演示]`，所有候选人姓名以“演示候选人D”开头。
薪资、公司、技能和项目均是测试设定，不代表市场行情或任何真实个人。

## 使用

- `sample-resumes/`：原根目录的 5 份小规模匹配测试简历，保留原文件名。
- `local/`：原 `local-data` 的本地私有资料与素材包，被 Git 和 Docker 忽略，不属于公开演示数据。

- `jds/`：可在页面「导入 JD」中选择单份 Markdown。
- `resumes/`：可在某个岗位内上传虚构简历，验证真实解析链路（需要模型与向量接口可用）。
- `dataset.json`：岗位、候选人以及关联关系的完整结构化数据。
- `python scripts/generate-demo-data.py`：从固定设定重新生成素材，不读取真实简历。
- `python scripts/seed-demo-data.py`：导入本地演示库；默认账号为本地管理员，也可设置
  `DEMO_USERNAME` / `DEMO_PASSWORD` / `DEMO_API_URL`。不要用于生产库。

导入脚本通过业务 API 创建岗位，通过数据库插入预设候选人结构。
`PARSED` 仅用于让预设资料参与匹配，不代表调用过 AI 解析。
记录的 `parse_error` 中有 `DEMO_FIXTURE:` 来源标记；前端显示为“演示预设”。
脚本不生成向量、不写假匹配分、不自动通过/淘汰候选人、不生成假面试报告。
重复导入按岗位名称及岗位内候选人名称跳过已有记录，不覆盖修改、不重置决策。
同一虚构简历可以关联多个岗位；24 是独立档案数，80 是岗位下的记录数。

## 场景覆盖

Java 订单/物流/ERP/高并发/搜索/初级岗位；Python RAG、Agent、LangGraph、Dify、
检索评测；React、Vue 与全栈；容器运维、数据工程、模型推理和质量工程。
每组包含不同技术背景，便于检查匹配解释、待核实技能、筛选和面试准备。
数据中的分组不构成招聘推荐或模型评测的标准答案。

## 用户提供的四份 PDF

原件不复制、不修改、不上传到外部模型，也不包含在此素材包中。
本地技术词摘要与来源映射保存在被 Git 和 Docker 忽略的 `demo-data/local/resume-samples/`。
摘要仅记录原文出现的技术词，不代表核实了个人职责、学历、年限或熟练度。
