# 第九阶段：跨模块验收与可重复检查

## 一条命令运行

在项目根目录执行：

```powershell
python scripts/verify-release.py
```

前置条件：已有Java/Maven、Node/npm、Python Playwright与Chrome、`ai-service/.venv`依赖，前端Vite已运行于5173。脚本不安装依赖，不启动Docker或修改环境配置；Vite未启动时明确报错，也可用 `--skip-browser` 仅执行后端与前端构建。已有其他本机前端端口可用 `--ui-url http://127.0.0.1:端口`，仅接受本机地址。

步骤为Maven clean verify（开启已有模拟Python跨服务测试）、前端构建、招聘进度/结果/流程协作三类页面回归；任一步失败停止并返回非零退出码。独立日志和report.json保存在被忽略的 `outputs/acceptance/时间戳/`，成功仅表示报告中列出的范围通过；跳过浏览器时不会声称页面已验证。清理target后再运行，避免统计旧测试报告。

## 新增真实HTTP业务链

`RecruitmentJourneyHttpTest`启动随机端口Tomcat，通过TCP请求和JWT完成以下流程，无直接设置SecurityContext或插入简历记录：

1. 注册管理员账号、创建公司，新增HR、只读HR与面试官并真实登录。
2. 建部门和岗位，授权EDITOR/VIEWER，multipart上传简历，经本地hash切分/向量及文档入库。
3. 校验总览文件名、匿名/无关成员/面试官读取限制，以及VIEWER不能修改结果。
4. EDITOR分配和排期，面试官存草稿，招聘端无法读取草稿且总览不计草稿。
5. 排期结束前提交被拒绝；测试时钟推进后提交成功、面试完成，总览显示评价但最终结果仍待定。
6. HR记录录用；旧版本请求返回409，归档、重新开启和历史保留正确。
7. 撤权后已有JWT不能继续读写；删除源简历后总览清空、面试入口失效。

此链使用独立H2数据库和本地hash向量，ResumeParser返回固定虚构资料；AiGateway断言未调用。不是DeepSeek/硅基流动或生产MySQL/Qdrant效果验收。已有Python跨服务测试仍单独覆盖Java/Python模拟链路。

`InterviewConcurrentTest`增加两位操作人同时决定/归档/开启的竞争校验：一人成功、一人版本冲突，仅增加一个版本和一条历史，历史记录实际操作人；另验证删除源简历与结果写入竞争不会产生孤立结果/历史。此并发验证基于H2，MySQL真实隔离级别与负载表现需单独验收。
