# 招聘流程可靠性：第一批开发与验收

日期：2026-11-07。本记录仅覆盖本轮新增修改，不代表已有未提交修改均已验收。

## 已实现

- 语义评分正常：规则分 70% + 语义分 30%，状态 `COMPLETE`。
- 模型异常、漏返、分数类型或范围不合法：不补默认 50 分，改用完整规则分，语义分为 null，状态 `DEGRADED`。前端显示“语义评分未完成”，用户可重新匹配。
- 未设置必须技能：跳过模型，使用规则分，状态 `RULE_ONLY`。
- 旧评分明细缺少状态：接口标为 `LEGACY`，页面提示重新确认；旧记录不能追溯判断是否曾经降级。
- 重新匹配更新原记录，保留结果 ID、创建时间及 HR 决策，不再删除重建全部结果。
- 评分字段显式更新，允许清空旧技能命中，防止 null 字段被 ORM 忽略。
- 模型调用位于事务外；独立写入服务使用短事务和岗位行锁，失败时完整回滚。
- 匹配前及写入时拒绝已关闭岗位；写入前核对已解析候选人 ID 集合，发生变化则要求重新匹配。
- 报告提示词将未提及技能定义为待核实，并解释规则评分与降级评分边界。

## 自动化验证

- `mvn test -q`：Java 回归，包含 H2 数据库上的匹配可靠性测试。外部 Qdrant 及部分真实向量评测按原测试配置跳过。
- `ai-service/.venv/Scripts/python.exe -m pytest -q`：27 项通过。
- 显式启用 `RUN_AI_E2E=true` 后执行 `PythonAiE2ETest`：通过。实际启动 Java/Python HTTP 服务，模型、embedding、rerank 提供方为本地模拟服务，数据库为 H2。
- 前端 `npm run build`：在真实路径 `E:\CodexWorkSpace\wibecoding\frontend` 构建通过，有现存大包体积警告。从旧目录联接路径构建可能触发 Vite 输出路径错误。

可靠性测试覆盖：模型调用不处于事务、正常加权、失败降级、漏返与非法评分、无需语义评分、关闭岗位、重匹配保留人工决策与 ID、清除旧技能命中、候选人列表变更拒绝写入、写入失败完整回滚。

## 真实服务验收待办

本轮检查时 Docker 引擎未运行，未执行真实模型、MySQL、Qdrant 全链路验收，也未进行浏览器交互验收。不将模拟测试作为模型效果或生产可用性证据。

启动环境后，使用脱敏或明确标记的合成材料验证：

1. 创建两个岗位，上传明显匹配、部分匹配、不匹配及信息缺失的简历。
2. 检查结构化字段与原文，核实匹配分、技能命中和待核实项。
3. 通过或拒绝候选人后重新匹配，确认决策与结果 ID 保留。
4. 模拟模型不可用，检查降级提示；恢复后重新匹配。
5. 生成面试题和报告，人工评审事实依据及评分解释。
6. 上传知识资料，检查真实向量检索、来源与跨账号隔离。
