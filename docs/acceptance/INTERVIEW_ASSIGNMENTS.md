# 面试官分配与人工评价（2026-11-08，第五阶段）

> 第六阶段已接入可选排期，已排期分配的评价须遵守结束时间及取消/未到场状态；旧未排期流程继续兼容。见[排期验收](INTERVIEW_SCHEDULING.md)。以下为第五阶段范围记录。

## 使用流程

公司管理员在成员管理创建HR或面试官（INTERVIEWER）账号，默认仍为HR，不能通过创建接口提升为公司管理员。认证响应新增companyRole用于导航，系统role仍为USER；后端权限以数据库成员关系为准，不信任浏览器中的角色。

岗位创建人或EDITOR在候选人行点击“分配面试”，选择同公司面试官，可分配多个面试官。仅支持已解析候选人，已关闭岗位不能新增分配；已安排的面试可继续评价，取消须明确撤销分配。只读成员不能分配。面试官不接受整岗位VIEWER/EDITOR授权，不能创建/导入岗位、浏览整个岗位候选人或操作招聘AI任务。

面试官登录自动进入“面试工作台”，仅显示本人获分配的候选人。详情包含必要的岗位要求、候选人结构化经历/技能和已有面试题，不返回联系人、邮箱、简历全文、文档ID、AI评估报告、HR决策或其他候选人。没有额外模型调用。

评价包含1～5分、建议通过/进一步核实/不通过、优势证据、待核实问题和总结。可保存不完整草稿，草稿只对本人可见；提交时评分、建议和总结必填，每个文本字段最多3000字。提交后不可修改，创建人/EDITOR可查看已提交结果；其他面试官不能查看或代填。面试评价不会自动改变HR筛选决策。

## 权限、并发与生命周期

- 分配、撤销和评价保存按岗位加锁，评价还锁定分配记录；相同候选人/面试官的重复有效分配复用原ID，避免重复安排。
- 保存携带version，过期版本返回409且不覆盖；提交后任何修改返回409。草稿冲突时保留浏览器未保存内容，用户明确重新加载后刷新版本；未保存关闭会提示放弃编辑。
- 写操作等待岗位锁后，分配去重、评价版本/状态及岗位授权/任务授权版本使用当前记录校验，避免事务已有旧快照导致撤权或版本判断过期。普通读取继续采用独立读取权限。
- 撤销后个人列表、详情、保存均拒绝；页面每10秒检查，保存收到403/404立即关闭。不能收回已看过的内容。
- 重分配生成新ID和新版本，不恢复旧草稿。已提交结果在撤销后仍供招聘操作人查看，原面试官不再访问该记录。
- 面试官或岗位创建人的同公司成员关系失效、面试官角色变化或其账号被软删除后，个人访问失效。分配人的EDITOR权限后来被撤销，不自动撤销此前有效的组织面试分配，应由当前招聘操作人明确撤销。
- 旧岗位仅在明确分配时核对并补齐company_id；有活动招聘任务时阻止该归属变更。原创建人、简历及知识数据归属不改。没有批量自动分配。
- 删除简历/岗位时清理相关面试分配与评价；操作记录保留操作元数据，不记录草稿正文。面试排期、外部通知、邀请链接、多轮流程模板及评价修订暂未实现。

## 接口与升级

公司新成员请求增加可选role=HR/INTERVIEWER；认证login/register/me响应包含可选companyRole，旧账号兼容。面试官菜单与招聘岗位页面分开，但服务端仍独立校验每个请求。

- GET /api/v1/interviews/assignments：本人有效分配及本人评价。
- GET /api/v1/interviews/assignments/{id}：本人分配的最小资料及评价。
- PUT /api/v1/interviews/assignments/{id}/evaluation：version、score、recommendation（PASS/HOLD/NO）、strengths、concerns、summary、submit；身份由服务端确定。
- GET /api/v1/recruitment/positions/{id}/interviews：创建人/EDITOR查看本岗位分配和已提交评价，草稿内容为空。
- POST /api/v1/recruitment/resumes/{id}/interviews：interviewerId，分配同公司面试官。
- POST /api/v1/recruitment/interviews/{id}/revoke：创建人/EDITOR撤销，重复调用幂等。

旧MySQL在此前阶段完成后备份，执行deploy/migrations/20261108_interview_assignments.sql，可重复运行；只新增recruitment_interview_assignment和recruitment_interview_evaluation。两份初始化SQL已同步，不自动创建角色/账号/分配/评价，不需要新密钥或外部服务。私人知识库、聊天与Python检索边界保持原有隔离。
