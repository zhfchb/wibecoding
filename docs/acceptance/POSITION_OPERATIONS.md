# 岗位招聘协作与任务责任（2026-11-08，第四阶段B）

## 权限范围

岗位创建人可在“协作授权”中选择只读协作（VIEWER）或招聘协作（EDITOR），并修改已有成员的权限。默认仍为只读；旧授权不会自动升级。招聘协作成员可进行候选人通过/淘汰、匹配、失败简历重解析、面试题与报告生成，并查看任务进度和最近100条招聘操作记录。

岗位修改、部门更换、关闭/删除、简历上传/删除和转授权仍由创建人负责。公司/系统管理员没有隐式越权。只读成员不能执行流程操作或查看任务/操作记录。私人知识库、聊天和Python检索回调的owner边界没有开放；协作任务使用岗位原创建人作为资料owner，不能由请求伪造。

canManage表示创建人权限，新增canOperate表示招聘流程操作权限。前端分别控制按钮并每10秒复查非创建人的岗位权限，后端对每次操作重新校验。权限降低为只读后保留已授权的读取入口；完全撤销后后续访问拒绝并清空页面。页面说明模型调用可能计费。

## 发起人、取消与撤权

新任务在同一提交事务中写入recruitment_task_actor：任务类型、ID、岗位、资料owner、实际发起人和授权版本。三类任务原owner_id及请求幂等逻辑保留，不把owner换成操作人。重复请求或活动任务复用，返回原任务及原发起人，不改写责任人。

任务响应新增actorId、canCancel。当前仍有操作权限的发起人可取消自己的任务，创建人可取消全部任务；其他招聘协作成员可查看进度但不能取消他人任务。重复取消不重复写操作记录。客户端传入actorId/ownerId无效。

执行前、匹配每批模型调用前、重解析每份简历写入前、报告搜索后生成前和最终结果事务写回前均复查发起人的权限。授权修改、撤销、重授与写回通过岗位锁串行，授权版本变化后旧任务不能恢复写回资格；失败标记AUTH_REVOKED，旧结果保留，须使用新请求重新提交。已发出的外部请求无法保证撤回或免计费；批量重解析中已完成的条目保留，未完成条目终止。

旧任务没有独立发起人记录，按原owner兼容执行和展示；不据此补写历史操作日志。后台执行不依赖Web登录上下文。recruitment_position_activity记录任务提交、取消和筛选决策的实际操作人；同一决策重复提交不重复记账。该列表是招聘操作记录，不宣称覆盖所有系统管理或历史行为。

## 接口与数据库

- 原协作授权PUT新增可选permission（VIEWER/EDITOR），不传按VIEWER处理；创建人可调整权限。
- 岗位响应新增canOperate；匹配/重解析/资料任务响应新增actorId、canCancel，旧字段保留。
- GET /api/v1/recruitment/positions/{id}/activity：创建人和招聘协作成员可查看最近100条记录。
- 新增升级脚本deploy/migrations/20261108_collaboration_operations.sql，前置为第四阶段A。备份后执行，可重复运行；新增授权permission/revision列和两张责任/操作记录表。旧授权默认VIEWER，无批量资料归属迁移、无历史发起人推断。两份初始化SQL已同步，无需新密钥、Python依赖或外部服务。

本地服务已更新：21个创建人岗位的canManage/canOperate均为true，旧companyId未批量补齐；操作记录为空、授权列表可读，已有匹配任务按原owner返回actorId/canCancel；OpenAPI和前端5173只读检查通过。真实MySQL验证范围为升级及读取，未创建测试EDITOR授权或付费AI任务。

手工验收：创建人打开岗位协作授权，将同公司成员设为“招聘协作”；另一个浏览器登录该成员，确认可筛选、发起任务、查看操作记录，但无上传/删除/授权按钮。若需要测试真实AI任务，由操作者按需提交并查看费用；创建人撤权后，未写回任务应失败并保留旧资料，重新授权后需重新发起任务。
