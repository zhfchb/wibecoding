# 面试排期与流程状态（2026-11-08，第六阶段）

## 已交付流程

岗位创建人或EDITOR在候选人的“分配面试”列表中为已有分配安排时间、调整排期、取消，并在计划结束后确认已完成或标记未到场。支持线上视频、现场、电话三种方式，填写地点/会议号/电话说明及可选http(s)会议链接。面试官只能读取本人当前安排，不能修改排期或读取管理端排期历史。

时间使用明确的IANA时区录入，UTC瞬间存为DATETIME(6)中的UTC值，JDBC以LocalDateTime显式转换，不依赖数据库连接或浏览器本地时区。响应同时包含UTC的startAt/endAt、原时区及该时区下的localStart/localEnd。开始须晚于服务器当前时间、精度为分钟、时长5～480分钟；夏令时不存在或重复的本地时间明确拒绝，不猜测偏移。

排期有独立版本，改期不修改评价版本，不覆盖正在编辑或已保存的草稿。改期、取消及未到场须填写原因，单项排期历史按版本保存时间、方式、地点、原因与实际操作人。会议链接不会被服务器访问，排期不会自动发送邮件、短信、外部通知或日历邀请。

## 进度与评价规则

分配/评价状态继续沿用ASSIGNED、DRAFT、SUBMITTED、REVOKED；排期状态单独使用SCHEDULED、CANCELLED、COMPLETED、NO_SHOW。flowStatus用于展示待排期、已排期、进行中、待确认结果、待评价、已评价、已取消、未到场或已撤销。

- 时间经过只展示“进行中/待确认结果”，不伪造实际到场或已完成。
- 有排期时，结束前可保存私有草稿，不能提交评价；结束后面试官提交评价可同步标记完成，已明确完成的面试继续等待评价。
- 取消排期保留分配与已保存草稿，但阻止评价写入。招聘操作人可重新排期，原草稿仍可继续使用；未到场、已完成或已提交评价的安排不能改期，需要新一轮时撤销并重新分配。
- 已关闭岗位不能新增或调整排期，但可取消、确认既有安排。撤销分配同时取消仍有效的时间槽；删除简历/岗位清理排期及历史。
- 面试官或成员关系失效后不能规划时间；必要时招聘操作人可撤销分配释放原预约。排期取消不等于撤销分配，完全收回资料访问仍用“撤销分配”。
- 评价不会自动改变HR筛选决策，草稿隐私及提交锁定保持原规则。旧未排期分配继续兼容第五阶段的评价流程，不补造历史时间。

## 冲突、权限与并发

相同面试官在不同岗位中的有效安排也会检查重叠；同一候选人简历记录不能与其他面试官安排重叠。使用半开区间，上一场结束时间等于下一场开始时间允许衔接。候选人范围以resume_id为准，不按姓名、邮箱自动合并跨岗位重复上传的简历。冲突消息不透露其他私有岗位或候选人的资料。

安排/改期使用READ_COMMITTED事务，先锁岗位/分配，再锁面试官账号行；相同候选人的操作由岗位锁串行，不同岗位共享面试官的操作由账号锁串行。获取资源锁后再读取重叠预约，避免旧快照漏检。排期版本不匹配返回SCHEDULE_VERSION，重叠返回SCHEDULE_OVERLAP；其他状态不允许操作时返回对应SCHEDULE_*业务冲突。变更、历史和操作记录在同事务内写入。

评价写入、撤销与排期更新共用岗位锁，并复查当前排期。面试官详情每10秒刷新排期，列表每30秒更新；排期变化只更新排期元数据，不覆盖未保存的评价内容。两个版本独立，冲突时明确刷新，不用旧请求覆盖新安排。

## 接口与部署

- PUT /api/v1/recruitment/interviews/{id}/schedule：version、localStart、localEnd、timeZone、mode（VIDEO/ONSITE/PHONE）、location、可选meetingUrl、reason。
- POST /api/v1/recruitment/interviews/{id}/schedule/state：version、action（CANCEL/COMPLETE/NO_SHOW）、reason。
- GET /api/v1/recruitment/interviews/{id}/schedule/history：当前岗位创建人/EDITOR可读历史。
- 原管理列表、个人列表、面试详情的assignment增加schedule和flowStatus；无排期时schedule=null。

完成前序数据库升级后备份，执行deploy/migrations/20261108_interview_scheduling.sql，可重复运行。只新增recruitment_interview_schedule及recruitment_interview_schedule_event，两份初始化SQL同步；不自动填充旧面试时间、创建真实排期或改变既有评价。不需要新依赖、服务或密钥。Clock.systemUTC为排期校验时间来源，测试固定Clock以验证时间边界。
