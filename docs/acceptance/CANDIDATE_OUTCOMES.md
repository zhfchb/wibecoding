# 招聘结果与归档（第七阶段）

> 后续状态：真实环境录用、归档、重新开启、历史及权限已在2026-11-08单样本流程验证，见[真实验收](LIVE_RECRUITMENT_ACCEPTANCE.md)。本文验证章节保留本阶段当时的范围。

## 操作与边界

岗位候选人列表新增“招聘结果”。岗位创建人及当前EDITOR可记录待定、录用、淘汰、候选人退出；每次变更须填写1～2000字原因。VIEWER可查看结果与历史，面试官及无岗位权限成员不可访问。系统ADMIN不绕过岗位权限。

最终结果独立于初筛hrDecision和面试建议；不从AI评分或面试评价推断录用。“录用”仅为HR记录，不代表发出Offer或入职确认。待定结果不能归档；归档后锁定结果修改，填写原因重新开启后可修正，原结果保留。关闭岗位仍可整理结果。

归档范围仅为招聘结果记录，不隐藏候选人，不自动取消任务或面试，不停止面试官评价，不删除资料。修改结果也不会自动通知候选人。若需要全流程结案，需另行明确活动任务、评价及撤销策略后开发。

每次操作保留结果、归档状态、原因、实际操作人和UTC时间。使用独立递增版本，岗位锁串行化写入，并在等待锁后重新确认简历存在；旧版本返回409 OUTCOME_VERSION，前端保留输入并要求刷新核对。源简历或岗位删除时清理结果及历史，归档不是不可删除的合规审计存储。

## 接口与升级

- GET `/api/v1/recruitment/resumes/{id}/outcome`：无记录返回版本0、待定、未归档，不回填数据。
- GET 同路径 `/history`：当前有读取权限者查看完整版本历史。
- POST 原路径：`version,action,outcome,reason`；action为DECIDE、ARCHIVE、REOPEN。

完成前序迁移并备份后执行 `deploy/migrations/20261108_candidate_outcomes.sql`。新增当前结果与历史两表，可重复执行，新库初始化已同步；无外部服务、依赖、密钥变更。
