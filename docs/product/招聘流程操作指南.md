# 从收到简历到完成面试评价

本项目是公司内部技术招聘协作工作台。AI提供参考，HR和岗位负责人负责核实并记录决定。招聘编制审批、外部渠道投递、自动消息通知、Offer和入职仍在系统外完成。

## 谁负责什么

| 人员 | 主要操作 |
| --- | --- |
| 公司管理员 | 维护公司/部门，创建HR与面试官账号；不自动获得全公司岗位权限 |
| 岗位创建人（本轮的岗位负责人） | 建立岗位、收录简历、授予协作权限；人工初筛、面试分配、汇总意见和最终结果 |
| EDITOR协作HR | 在获授权岗位初筛、分配面试、安排排期、记录沟通；不冒用负责人写汇总 |
| VIEWER协作成员 | 查看获授权资料、跟进记录及负责人汇总，不修改招聘业务 |
| 面试官 | 只查看分配给自己的候选人必要信息、面试题和安排；保存个人草稿、提交评价 |

负责人沿用岗位创建人身份，没有新引入独立“用人经理”权限。负责人汇总与面试官自己的评价是两类记录。

## 一个Java岗位怎样推进

1. 公司管理员建立成员账号。HR在岗位工作台创建Java岗位，写明必须/加分技能和薪资，上传收到的简历。
2. 查看“招聘流程 · 下一步”。先处理解析失败项，再执行匹配，核对证据后人工通过或淘汰初筛；参考分不自动录用人。
3. 在候选人行点击“跟进与汇总”，写下已经发生的意向沟通或待核实事项，可选下次跟进时间。时间是记录，不会发送提醒。
4. 通过初筛后准备面试资料，在“分配面试”中选择第1～10轮、同公司面试官，再安排时间和方式；HR另行通知候选人。一个轮次可由多个面试官参与，同面试官同轮重复分配复用原记录。
5. 面试官登录“我的面试安排”，按待准备、进行中、待提交评价等任务筛选。面试前读资料，面试后写证据；草稿仅本人可见，提交后锁定。存在排期时结束前不能提交。
6. HR在“分配面试”里查看各轮已提交评价。岗位创建人在“跟进与汇总”选择“负责人汇总意见”，记录共识、分歧和待核实项；不能读取或引用未提交的私有草稿。
7. 决定补面时人工新增轮次并安排时间；决定结束时在“招聘结果”记录待定、录用、淘汰或退出及原因，按需归档。轮次不自动晋级，评价、汇总均不自动覆盖最终结果。

旧面试默认第1轮。不同轮次的排期与评价独立，原有权限、版本冲突、时间冲突和撤销访问检查保持有效。没有自动多轮通过门槛；是否进入下一轮由HR决定。

## 沟通与汇总记录的边界

记录追加保存，包含记录人和时间，分页查看，不允许覆盖旧记录；写错可追加说明。内容最多3000字符，跟进时间需晚于保存时的当前时间。保存结果未知时使用“重试确认保存”，复用原请求标识，避免重复新增；刷新或离开后先查历史记录再新增。

跟进记录不是消息发送凭据，负责人汇总不是招聘结果审批，更不是Offer。请只记实际发生的沟通和有证据支持的判断。删除源简历会连带清理其跟进/汇总记录。
