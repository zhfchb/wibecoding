# 择序 · 技术招聘工作台

“择序”为本轮界面改版的暂定名称，可替换。

## 为谁解决什么问题

服务中小企业负责技术岗位招聘的 HR，尤其是没有完整招聘系统、需要手工整理岗位和多份简历的用户。
帮助用户将岗位要求、候选人资料、匹配依据和面试准备放进同一个工作流程。
AI 提取与整理信息、提供参考；HR 核实候选人信息并作最终筛选决策。

## 主要使用方法

1. 登录后进入岗位工作台，创建岗位或导入已有 JD，核对技能、经验等要求。
2. 进入该岗位，上传候选人简历，检查信息是否成功解析。
3. 执行人岗匹配，查看参考分、技能命中与待核实技能，人工决定是否通过初筛。
4. 为通过的人选准备面试题和评估报告，围绕具体经历进一步核实。

招聘资料库用于上传岗位说明、招聘制度、技术评价标准等参考文档。
资料问答基于已上传的文档提供回答与来源。
内容审核用于生成、修改和确认资料草稿，不等同于候选人审批。

## 导航与界面约定

- 岗位工作台是默认入口，招聘支持功能位于次级分组。
- 登录页说明用途、适用人群和操作路径，不展示默认账号或虚构业务成果。
- 空状态提供下一步操作；失败状态提供重试，不将请求失败当作没有数据。
- 概况仅展示真实接口数据：开放岗位、收录简历、已有候选人的开放岗位。
- 创建岗位后进入该岗位的候选人页；支持搜索岗位、部门、城市和筛选岗位状态。
- 无已解析简历或岗位已关闭时不能执行匹配。
- 对 HR 使用业务词汇，技术模型和框架名称不作为主要导航。

## 当前边界

本轮主要改变前端定位、导航、视觉和操作引导，复用既有业务 API。
不宣称已具备面试排期、发邀约、组织协作权限、完整 ATS 或招聘渠道集成。
现有工作流、匹配效果与模型连接仍需分别验证；界面改版不代表修复向量服务网络。

## 本轮验证

在本地浏览器验证了登录跳转、空岗位引导、创建临时岗位后跳转、搜索无结果、
空简历禁用匹配、辅助功能入口及 390px 手机导航；前端生产构建通过。
用于 UI 验收的岗位在验证后清理。真实简历解析和 RAG 不属于本轮验收。
