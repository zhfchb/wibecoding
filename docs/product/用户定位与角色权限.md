# 用户定位与权限规划

产品定位：面向中小型技术团队的AI招聘协作工作台。主要用户为公司管理员、HR/招聘负责人、技术面试官/用人负责人；候选人暂不直接登录。同一人未来可兼任多个岗位角色。

| 人群 | 目标职责 | 当前状态 |
| --- | --- | --- |
| 公司管理员 | 公司、部门、成员及权限维护 | 公司资料、成员和部门管理已实现 |
| HR/招聘负责人 | 岗位、简历、初筛及流程推进 | 管理自己岗位，可向指定同公司成员授权只读或招聘流程协作 |
| 面试官/用人负责人 | 按候选人分配、面试准备与人工评价 | 已有独立面试官角色/工作台，仅查看本人获分配候选人的最小资料，草稿私有、提交锁定 |
| 候选人 | 外部投递与进度查询 | 不在当前范围 |

## 分阶段执行

1. 已完成：公司基础与资料完善，按成员关系校验公司管理员/HR，角色不等同于系统ADMIN/USER。
2. 已完成：平级部门目录、公司内唯一名称、管理员增改启停、HR只读。无物理删除，无组织树。
3. 已完成：岗位关联正式部门ID，新选择校验当前公司且启用；旧部门文本保留，通过只读核对清单及详情页逐项关联，不自动猜测合并。新岗位记录company_id，旧岗位显式关联后补齐，创建人访问范围不变。
4. 已完成第四阶段A：岗位只读协作。创建人向指定同公司成员授权，开放岗位、候选人、匹配结果和已有题目/报告读取；撤销和成员关系实时校验。写操作及后台任务仍归创建人，私人知识库、聊天和Python检索回调保持原owner隔离。见[协作验收](../acceptance/POSITION_COLLABORATION.md)。
5. 已完成第四阶段B：可选EDITOR权限，开放筛选和三类AI任务；数据owner与实际actor分离，任务幂等复用保留原发起人，取消限定为创建人/当前有权限的发起人，撤权与重授版本校验保护写回。私人检索不扩大，岗位修改/上传删除/转授权仍由创建人负责。见[流程协作验收](../acceptance/POSITION_OPERATIONS.md)。
6. 已完成第五阶段：INTERVIEWER成员、候选人级分配/撤销、必要资料与已有题目读取、私有草稿、提交锁定及版本冲突校验。评价不自动决定通过/淘汰。见[面试验收](../acceptance/INTERVIEW_ASSIGNMENTS.md)。
7. 已完成第六阶段：面试排期、时区与冲突检查、改期/取消、完成/未到场及历史；排期变化不覆盖评价草稿。见[排期验收](../acceptance/INTERVIEW_SCHEDULING.md)。当前不自动向外发送消息或日历邀请。
8. 已完成第七阶段：招聘结果与归档，由HR记录结果及原因，独立版本与历史；VIEWER只读，面试官不可见。归档仅锁定结果记录。见[结果验收](../acceptance/CANDIDATE_OUTCOMES.md)。

目前一人一家公司，不支持跨公司切换、既有账号直接合并、成员停用/复杂角色矩阵。公司目录可共享，招聘资料按岗位显式授予只读或流程协作权限；系统ADMIN声明不绕过公司或岗位权限。各阶段独立验证、Git提交，保留现有数据与已验证边界。

9. 已完成第八阶段招聘进度总览：岗位内结果/归档统计、搜索、组合筛选及已有评价仍待决定提示；不自动决策，见[进度验收](../acceptance/RECRUITMENT_PROGRESS.md)。
