# 学习路线

> 历史与学习资料：其中框架、接口及完成状态可能属于旧版本，当前实现以根 README、AI 迁移说明和实际代码为准。

> 本文档面向刚接触本项目技术栈的同学,目标是从零理解项目用到的每一项技术,并能独立开发和面试。
> 定位:入门友好,多用类比,少用术语。每一项技术都标注"为什么学""学到什么程度""项目里对应哪段代码"。

## 0. 学习顺序总览

```
Java 基础(已具备)
    ↓
Spring Boot(项目骨架)
    ↓
MySQL + MyBatis-Plus(数据持久化)
    ↓
Redis(缓存与会话)
    ↓
AI 基础:LLM 调用(DeepSeek + LangChain4j)
    ↓
RAG:Embedding + 向量检索(Qdrant)
    ↓
Agent:Function Calling(工具调用)
    ↓
工程化:Docker + 测试 + 文档
    ↓
进阶:LangGraph4j(复杂 Agent 工作流)
```

**核心思路**:先学后端基本功(能写 CRUD),再学 AI 接入(能调 LLM),最后学 AI 应用模式(RAG/Agent)。这样每一步都能产出可运行的代码,不会卡在理论里。

## 1. Spring Boot(项目骨架)

### 为什么学
Spring Boot 是 Java 后端的事实标准,几乎所有 Java 招聘都要求。本项目用它做 Web 接口、依赖注入、配置管理。

### 学到什么程度
- 理解"约定优于配置":为什么不用写 XML 就能跑起来
- 会用 `@RestController` / `@Service` / `@Configuration` 三件套
- 会用 `application.yml` 管理配置,理解 Profile 机制
- 理解依赖注入(DI):对象不用 `new`,交给 Spring 管理

### 类比理解
> Spring Boot 像一家餐厅的「管理体系」:`@RestController` 是服务员(接单)、`@Service` 是厨师(干活)、`@Configuration` 是餐厅规章(配置)。你不用关心服务员怎么把单子传给厨师,Spring 自动帮你接线(依赖注入)。

- 接口层:[controller/](../../src/main/java/com/example/agent/controller) — 三个 `@RestController`
- 业务层:[service/impl/](../../src/main/java/com/example/agent/service/impl) — `@Service` 实现类
- 配置:[config/](../../src/main/java/com/example/agent/config) — `@Configuration` 配置类

## 2. MySQL + MyBatis-Plus(数据持久化)

### 为什么学
数据要存盘,不能程序一关就没了。MySQL 是最流行的关系型数据库,MyBatis-Plus 让你少写 SQL。

### 学到什么程度
- 理解表、行、列、主键、外键
- 会写基础 CRUD SQL(`SELECT` / `INSERT` / `UPDATE` / `DELETE`)
- 理解索引为什么能加速查询(及为什么不能滥用)
- 会用 MyBatis-Plus 的 `BaseMapper`(继承就能 CRUD)
- 会用分页插件、逻辑删除

### 类比理解
> MySQL 像一个 Excel 文件:每个 Sheet 是一张表,每行是一条记录,每列是一个字段。主键是行号,索引是目录页(翻到目录页直接定位,不用一页页翻)。
>
> MyBatis-Plus 像一个智能助手:你告诉它"这是个 User 表",它自动帮你生成增删改查方法,不用手写 SQL。

### 项目里的对应代码

- Mapper:[mapper/DocumentMapper.java](../../src/main/java/com/example/agent/mapper/DocumentMapper.java) — 继承 `BaseMapper` 即有 CRUD
- 配置:[MybatisPlusConfig.java](../../src/main/java/com/example/agent/config/MybatisPlusConfig.java) — 分页插件
- 建表:[schema.sql](../../src/main/resources/schema.sql)
- 使用:[KnowledgeServiceImpl.java](../../src/main/java/com/example/agent/service/impl/KnowledgeServiceImpl.java) — `documentMapper.insert(entity)`

## 3. Redis(缓存与会话)

### 为什么学
有些数据访问频繁但又容易变(如会话上下文),放数据库太慢,放内存又怕丢失。Redis 是"内存数据库",快且能持久化。

### 学到什么程度
- 理解 Redis 是 key-value 内存数据库
- 会用 `SET` / `GET` / `DEL` 基础命令
- 理解 TTL(过期时间):数据到点自动删除
- 理解 String 数据结构(本项目只用这个)
- 知道什么时候该用 Redis(缓存、会话、限流),什么时候不该用(强一致性数据)

### 类比理解
> Redis 像桌上的便签本:MySQL 是档案柜(慢但全),Redis 是便签(快但临时)。会话上下文这种"用完就扔"的数据写便签,重要数据归档。
>
> TTL 像便签上的"3 天后撕掉"标记:到点自动消失,不用人管。

### 项目里的对应代码
- 抽象:[SessionStore.java](../../src/main/java/com/example/agent/service/SessionStore.java) — 会话存储接口
- 生产实现:[RedisSessionStore.java](../../src/main/java/com/example/agent/service/impl/RedisSessionStore.java) — 用 `StringRedisTemplate`
- 测试实现:[MemorySessionStore.java](../../src/main/java/com/example/agent/service/impl/MemorySessionStore.java) — 不依赖 Redis
- 配置:[application.yml](../../src/main/resources/application.yml) — `spring.data.redis.*`

### 学习资源
- 菜鸟教程 Redis 篇(只看 String 和 Key 命令)
- 理解持久化:掘金搜"Redis RDB AOF 区别"(了解概念即可)

## 4. AI 基础:LLM 调用(DeepSeek + LangChain4j)

### 为什么学
AI 时代,后端开发要会"调用大模型"。DeepSeek 是国产高性价比 LLM,LangChain4j 是 Java 调用 LLM 的标准库。

### 学到什么程度
- 理解 LLM 是什么:输入文本,输出文本,本质是"预测下一个词"
- 理解 token:LLM 按 token 计费和计算长度,1 个汉字≈1-2 token
- 会用 OpenAI 兼容协议调 LLM(DeepSeek 兼容这个协议)
- 理解 system / user / assistant 三种角色消息
- 会用 LangChain4j 的 `OpenAiChatModel`

### 类比理解
> LLM 像一个读过海量书的"超级实习生":你给个题目,它能写出像模像样的答案,但它不联网、不会算数、可能胡编(幻觉)。你的工作是"给它正确的问题"和"检查它的答案"。
>
> 三种消息角色像对话中的分工:`system` 是"你是个 XX 助手"(设定身份),`user` 是用户提问,`assistant` 是 AI 回答。

### 项目里的对应代码
- 配置:[DeepSeekConfig.java](file:///e:/Projects/wibecoding/src/main/java/com/example/agent/config/DeepSeekConfig.java) — 创建 `OpenAiChatModel` Bean
- 单轮对话:[ChatServiceImpl.java](../../src/main/java/com/example/agent/service/impl/ChatServiceImpl.java) — 最简单的 LLM 调用
- 流式输出:[RagChatServiceImpl.java](../../src/main/java/com/example/agent/service/impl/RagChatServiceImpl.java) — `OpenAiStreamingChatModel` 逐 token 返回

### 学习资源
- DeepSeek 官方文档:platform.deepseek.com(看 API 调用部分)
- LangChain4j 官方文档:langchain4j.dev(看"Quick Start"和"Chat Models")

## 5. RAG:Embedding + 向量检索(Qdrant)

### 为什么学
LLM 不知道你公司的私有数据(比如内部文档),RAG(检索增强生成)让 LLM"翻着你的资料回答问题",是企业 AI 应用最主流的模式。

### 学到什么程度
- 理解 RAG 全流程:上传文档 → 切分 → Embedding → 存向量库 → 检索 → 拼 prompt → LLM 回答
- 理解 Embedding:把文本变成向量(一串数字),语义相近的文本向量也相近
- 理解向量检索:找"距离最近"的几条文档(余弦相似度)
- 会用 Qdrant 向量数据库
- 理解切分策略:为什么要切?重叠窗口有什么用?

### 类比理解
> RAG 像"开卷考试":
> - 上传文档 = 把课本带进考场
> - 切分 = 把课本拆成一页页方便翻
> - Embedding = 给每页内容打"语义坐标"
> - 向量检索 = 翻到和问题最相关的几页
> - 拼 prompt + LLM = 看着翻到的页子写答案
>
> Embedding 像"把每段文字放到语义坐标系里":描述"狗"的文字和描述"犬"的文字坐标接近,和描述"汽车"的坐标远。向量检索就是"找坐标最近的邻居"。

### 项目里的对应代码
- 切分:[DocumentChunker.java](../../src/main/java/com/example/agent/rag/DocumentChunker.java)
- Embedding:[LexicalHashEmbeddingModel.java](../../src/main/java/com/example/agent/rag/LexicalHashEmbeddingModel.java) — 本地 hash 演示版
- 向量库:[InMemoryVectorStore.java](../../src/main/java/com/example/agent/rag/InMemoryVectorStore.java) / [QdrantVectorStore.java](../../src/main/java/com/example/agent/rag/QdrantVectorStore.java)
- 全流程:[RagChatServiceImpl.java](../../src/main/java/com/example/agent/service/impl/RagChatServiceImpl.java) — `chat()` 方法
- 评估:[RagEvaluationTest.java](../../src/test/java/com/example/agent/rag/RagEvaluationTest.java) — Recall@K 指标

### 学习资源
- 概念:掘金搜"RAG 检索增强生成 原理"(看 1 篇综述)

## 6. Agent:Function Calling(工具调用)

### 为什么学
LLM 本身只会"说话",不会"做事"(查时间、算数、调 API)。Function Calling 让 LLM 决定"该用哪个工具",由代码执行后把结果返回给 LLM。

### 学到什么程度
- 理解 Agent = LLM + 工具
- 理解 Function Calling 流程:LLM 看到问题 + 工具描述 → 决定调哪个工具 → 代码执行 → 结果回传 LLM → LLM 给最终答案
- 会用 LangChain4j 的 `@Tool` 注解和 `AiServices`
- 理解"LLM 不直接执行工具,只决策调用哪个"——执行靠代码

### 类比理解
> Agent 像一个聪明的经理:它自己不干活,但知道手底下有谁(工具清单)。收到任务时它判断"这事该让时间工具去做",把活派下去,拿到结果后汇总汇报。
>
> Function Calling 流程像这样:
> 1. 你问"现在几点?"
> 2. LLM 想:这需要查时间,有个 `getCurrentTime` 工具,我调它
> 3. LLM 输出:调用 `getCurrentTime`
> 4. 代码执行 `getCurrentTime()`,返回 "14:30"
> 5. LLM 拿到 "14:30",组织成自然语言:"现在是下午 2 点 30 分"

### 项目里的对应代码
- 工具:[tools/TimeTools.java](file:///e:/Projects/wibecoding/src/main/java/com/example/agent/tools/TimeTools.java) — `@Tool` 注解
- 工具:[tools/CalculatorTools.java](file:///e:/Projects/wibecoding/src/main/java/com/example/agent/tools/CalculatorTools.java)
- Agent:[AgentServiceImpl.java](../../src/main/java/com/example/agent/service/impl/AgentServiceImpl.java) — `AiServices` 动态代理

### 学习资源
- LangChain4j 文档"Tools"章节
- OpenAI 文档"Function Calling"章节(理解协议)
- 概念:掘金搜"Agent Function Calling 原理"

## 8. 进阶:LangGraph4j(复杂 Agent 工作流)

### 为什么学
当 Agent 需要循环(重试)、多步协作(多 Agent)、人工审批时,LangChain4j 的线性模式不够用,LangGraph4j 用"有向图"编排复杂流程。

### 学到什么程度(规划中)
- 理解"图编排"vs"线性调用"的区别
- 理解状态在节点间如何传递
- 理解循环和条件分支
- 会做自适应 RAG(检索质量不达标 → 重写查询 → 重试)

### 类比理解
> LangChain4j 像流水线:一道工序接一道,走到底。
> LangGraph4j 像流程图:可以有分支(条件判断)、循环(重试)、暂停(等人审批)。
>
> 自适应 RAG 像这样:
> 1. 检索文档
> 2. 评估相关性(不达标?)
> 3. 不达标 → 改写查询 → 回到第 1 步(循环)
> 4. 达标 → 生成答案

### 项目里的对应代码
- 规划中,见 [docs/development/项目架构大纲.md](../development/项目架构大纲.md) §9 M8

### 学习资源(先看概念)
- LangGraph4j GitHub:github.com/langgraph4j/langgraph4j
- 概念:搜"LangGraph vs LangChain"(理解为什么需要图编排)
