# 公司管理分阶段计划

每阶段独立验证并提交Git，分支为 codex/company-management。

用户定位与当前实现/规划边界见[用户定位与角色权限](../product/用户定位与角色权限.md)。部门完成后，先独立接入岗位关联，再做共享权限与面试官分配，避免把组织目录可见误当作简历全公司可见。

1. 已完成公司基础与资料完善：公司资料、省市、一人一家公司、公司管理员/HR成员、管理员创建全新HR账号。旧账号首次访问公司入口时，在锁定账号后创建独立空间；不合并旧账号及数据。公司角色与系统 ADMIN/USER 独立。
2. 已完成部门目录：同公司唯一名称、新增/编辑/停用/启用，管理员维护，HR只读，不物理删除。公司管理菜单增加部门管理。
3. 已完成岗位关联：新岗位可选启用部门，company_id与原创建人user_id并存；旧岗位不猜测归属，核对后逐项手动关联。部门改名后展示新名称，停用后保留既有关联。
4. 已完成第四阶段A岗位只读协作：创建人向指定同公司成员授权/撤销，统一验证岗位、候选人及已有资料读取，任务与私人检索保持创建人/owner边界。见[协作验收](../acceptance/POSITION_COLLABORATION.md)。
5. 已完成第四阶段B流程协作：EDITOR可筛选及操作三类AI任务，actor与owner分离、授权版本保护写回、取消责任规则及操作记录已实现。岗位修改/上传删除/转授权继续由创建人负责，私人检索权限保持原边界。见[流程协作验收](../acceptance/POSITION_OPERATIONS.md)。
6. 已完成第五阶段面试官：候选人级分配/撤销、独立工作台与最小资料、私有草稿/提交锁定、版本与撤销写入保护。评价不自动改变HR决策，见[面试验收](../acceptance/INTERVIEW_ASSIGNMENTS.md)。
7. 已完成第六阶段面试排期与流程状态：时区、时间冲突、改期/取消、完成/未到场、版本保护和排期历史。见[排期验收](../acceptance/INTERVIEW_SCHEDULING.md)。没有自动发送外部通知或日历邀请。
8. 已完成第七阶段招聘结果与归档：由HR明确记录待定/录用/淘汰/退出及原因，归档与重新开启保留版本历史。归档不自动终止其他流程。见[结果验收](../acceptance/CANDIDATE_OUTCOMES.md)。

目前公司目录可共享，招聘资料默认创建人可见，按岗位授予指定成员只读或招聘流程协作权限。暂不支持加入既有账号、跨公司转移、公司成员停用/角色变更、多公司切换或组织树。

已有数据库需依次执行公司基础、公司资料、部门目录、岗位部门关联升级，各脚本见验收及环境文档；不要对review_position_departments.sql的查询结果自动执行UPDATE。新库初始化已包含各表/列。本地数据库已备份升级，原有岗位/简历/向量/任务归属未批量迁移，组织与权限升级阶段未调用付费模型；后续真实验收已在独立虚构测试公司调用模型。

第二阶段验收见[部门验收](../acceptance/DEPARTMENTS.md)。

第三阶段验收见[岗位部门验收](../acceptance/POSITION_DEPARTMENTS.md)。历史岗位未批量关联，逐项核对部门或明确授权时确认公司归属。面试官分配及排期已在后续阶段实现。

9. 已完成第八阶段招聘进度总览：岗位内结果/归档统计、搜索、组合筛选及已有评价仍待决定提示；不自动决策，见[进度验收](../acceptance/RECRUITMENT_PROGRESS.md)。

10. 已完成第九阶段隔离环境跨模块HTTP及并发验收、统一回归脚本；真实模型单样本招聘流程已在后续完成，生产部署及性能验收仍待执行。见[统一验收](../acceptance/RELEASE_VERIFICATION.md)。
