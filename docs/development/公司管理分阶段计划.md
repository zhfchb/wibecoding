# 公司管理分阶段计划

每阶段独立验证并提交Git，分支为 codex/company-management。

用户定位与当前实现/规划边界见[用户定位与角色权限](../product/用户定位与角色权限.md)。部门完成后，先独立接入岗位关联，再做共享权限与面试官分配，避免把组织目录可见误当作简历全公司可见。

1. 已完成公司基础与资料完善：公司资料、省市、一人一家公司、公司管理员/HR成员、管理员创建全新HR账号。旧账号首次访问公司入口时，在锁定账号后创建独立空间；不合并旧账号及数据。公司角色与系统 ADMIN/USER 独立。
2. 已完成部门目录：同公司唯一名称、新增/编辑/停用/启用，管理员维护，HR只读，不物理删除。公司管理菜单增加部门管理。
3. 已完成岗位关联：新岗位可选启用部门，company_id与原创建人user_id并存；旧岗位不猜测归属，核对后逐项手动关联。部门改名后展示新名称，停用后保留既有关联。
4. 下一阶段公司招聘数据共享：明确岗位负责人、协作成员及资料访问范围，覆盖招聘、简历、任务、知识检索和Python回调。迁移前备份并确认归属；不能简单把ownerId替换为companyId，也不能默认全员可见所有简历。
5. 后续面试官与用人负责人：显式分配岗位/候选人、范围内查看、面试准备与评价。在共享边界测试通过前不开放面试官角色。

目前公司目录可共享，招聘资料仍按原账号隔离。暂不支持加入既有账号、跨公司转移、成员停用/角色变更、多公司切换或组织树。

已有数据库需依次执行公司基础、公司资料、部门目录、岗位部门关联升级，各脚本见验收及环境文档；不要对review_position_departments.sql的查询结果自动执行UPDATE。新库初始化已包含各表/列。本地数据库已备份升级，原有岗位/简历/向量/任务归属未批量迁移，未调用付费模型。

第二阶段验收见[部门验收](../acceptance/DEPARTMENTS.md)。

第三阶段已完成岗位正式关联部门，详见[岗位部门验收](../acceptance/POSITION_DEPARTMENTS.md)。历史岗位保持未关联，通过只读清单与页面核对后手动关联；下一阶段处理公司内招聘数据共享，面试官分配仍未开放。
