# 公司管理分阶段计划

每阶段单独验证并提交Git，分支为 codex/company-management。

用户定位与当前实现/规划边界见[用户定位与角色权限](../product/用户定位与角色权限.md)。部门完成后，先独立接入岗位关联，再做共享权限与面试官分配，避免把组织目录可见误当作简历全公司可见。

1. 公司基础：公司资料、一个账号一个公司、公司管理员/HR成员、管理员创建全新HR账号。旧账号首次访问公司入口时，在锁定账号后创建独立空间；不合并旧账号及数据。公司角色与系统 ADMIN/USER 独立，后端实际校验成员角色。
2. 部门：同公司唯一名称、新增/编辑/停用；被引用时不能物理删除。公司管理菜单增加部门管理。
3. 岗位与协作：正式department_id、company_id和原创建人并存，梳理招聘、简历、任务、知识库及Python回调的数据归属，迁移前备份并确认归属；不能简单把ownerId替换为companyId。

第一阶段不开放公司内招聘资料共享，成员页面明确说明现有招聘资料仍按账号隔离。暂不支持加入既有账号、跨公司转移、成员停用/角色变更、多公司切换或组织树，避免提供尚未覆盖旧JWT与后台任务权限的控制。

第一阶段已有数据库需执行 deploy/migrations/20261108_company_foundation.sql；新库初始化SQL已包含新表。公司空间按需建立，未改动原有岗位、简历、向量或任务归属。未启动正式服务、未迁移真实数据库或调用付费模型。

第二阶段已完成部门目录及权限验证，详见[部门验收](../acceptance/DEPARTMENTS.md)。实际本地Docker数据库已备份升级，旧岗位部门文本未迁移；上文第一阶段未启动服务为该阶段的历史记录。下一阶段只接入岗位正式部门关联，共享权限和面试官分配继续单独推进。
