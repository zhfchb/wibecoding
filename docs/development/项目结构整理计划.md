# 第一版结构整理计划

本轮从2026-11-16功能收尾基线开始，采用业务模块组织。保持HTTP路径、请求响应、表名、模型设置和运行端口兼容；移动文件与业务修改分别提交，不引入新框架或微服务。

## 盘点与归属

| 模块 | 内容 |
| --- | --- |
| company | 公司、部门、成员与公司资料选项 |
| recruitment | 岗位、简历、匹配、候选人跟进、结果、共享权限及招聘任务授权 |
| interview | 面试题/报告、资料生成任务、分配、轮次、排期、评价 |
| knowledge | 资料上传、切片、检索、向量存储及Python检索回调 |
| chat | 普通/资料问答、会话、来源、内存/Redis会话存储 |
| review | 人工内容审核及多Agent任务状态 |
| assistant | 通用Agent工具调用入口，与内容审核区分 |
| integration.ai | Python AI网关 |
| security | 认证、用户、JWT与HTTP安全处理 |
| config / exception | 跨业务基础配置、健康检查与统一异常处理 |

每个模块按实际规模使用api、dto、service、entity、mapper、config子包；已有接口与实现保留，以减少纯整理中的行为变更。批量任务在所属业务下保留独立目录。

## 顺序与验收

1. 保存当前接口路径/方法快照，按模块移动Java主代码和测试，更新导入、Mapper扫描、OpenAPI扫描及当前文档链接；编译及完整后端验证。
2. 前端页面/组件/钩子按业务归拢，共享HTTP客户端独立，业务API靠近业务；拆出岗位页中的两个面试资料抽屉。逐步构建及页面回归。
3. Python拆清应用组装、简历解析和业务路由位置，保留启动入口app.main:app、内部路由及依赖注入行为；验证模拟跨服务链。
4. 脚本提供按启动维护/演示/验收的分类导航，保留现有命令入口兼容；同步结构说明、源码阅读路线和当前文档。
5. 完整217项基线测试与7组页面回归、本地运行复核和接口路径快照对比；按阶段小提交。

## 依赖边界

认证依赖用户持久化；公司成员使用认证用户。招聘负责岗位权限和任务授权，面试通过这些权限访问候选人。招聘删除流程调用面试清理，面试读取岗位/简历，因此当前存在显式跨模块协作；本轮记录该边界，不声称已经实现严格单向依赖或完整DDD隔离。向量与模型调用属于适配边界，不能把模型SDK扩散进业务控制器。

历史变更日志和验收报告保留其时间语境；当前入口文档更新到新目录。数据库、原会话、演示账号和模型密钥均不作为整理对象。
