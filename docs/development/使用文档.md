# 使用文档

更新于2026-11-09。当前架构为React + Spring Boot + Python FastAPI / LangChain / LangGraph，模型由Python调用。历史Java AI框架已移除。

本轮一致性修复后，上传完整落库才返回成功；删除立即禁止后续检索，向量物理清理在后台失败重试。已有库先执行[迁移指南](../../deploy/migrations/README.md)第13项再更新后端，细节见[修复验收](../acceptance/CONSISTENCY_FIXES.md)。

## 启动与升级

首次启动按[根README](../../README.md)配置`.env.local`、构建后端并启动本地Compose，然后设置前端`API_PROXY_TARGET=http://127.0.0.1:18080`并启动Vite。前端默认5173，Java API18080。已有数据卷先备份并执行[增量迁移](../../deploy/migrations/README.md)，不要重跑初始化SQL或删除数据卷。

需要单独启动Python开发服务时，在`ai-service`目录使用Python3.12虚拟环境安装`requirements.lock`，设置`AI_SERVICE_TOKEN`、`DEEPSEEK_CLIENT_API_KEY`、`RAG_EMBEDDING_API_KEY`及`JAVA_SERVICE_URL`，运行`python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`；Java设置相同内部令牌和`AI_SERVICE_BASE_URL=http://localhost:8000`。原Java本地配置中的密钥不会自动迁入Python环境。

## 公司管理员

登录后从公司管理进入公司资料，完善名称、简介、行业、规模和省市等信息；其他字段按页面提示选填。新增HR或面试官成员账号，维护部门名称、说明和启用状态。部门停用保留历史岗位关联，不物理删除。

公司角色与系统角色不同。公司管理员只能访问自己创建或获授权的岗位，不自动读取全公司简历。

## HR与协作成员

1. 创建岗位或导入JD，核对必须技能、年限、学历和薪资；薪资上限至少高于下限1k。新岗位可关联启用部门，旧岗位核对后逐项关联。
2. 上传简历，核对姓名、技能、经验和解析状态。失败资料可根据保存原文后台重试，不需再次上传或向量化。
3. 发起人岗匹配，等待任务完成，阅读规则/语义评分及证据，人工通过或淘汰初筛。模型建议不自动转为录用。
4. 创建人可授予指定同公司成员VIEWER或EDITOR。VIEWER只读，EDITOR可推进流程；岗位修改、上传删除、转授权仍由创建人执行。
5. 为候选人生成定制面试题和报告，任务失败时保留原内容，核对错误后重试；可取消的任务按页面权限处理。
6. 分配面试官，安排时间、时区、方式及地点。系统校验面试官/同简历时间冲突；改期或取消填写原因。
7. 查看已提交评价后记录最终招聘结果和原因，按需归档或重新开启。并发修改出现版本冲突时刷新核对，再重新提交。
8. 从招聘进度总览按结果、归档和跟进状态筛选；“已有评价、仍待决定”仅作人工跟进提示。

关闭岗位后不能新增或修改排期，但可处理已有安排及整理最终结果。归档只锁定招聘结果，不自动取消面试或任务；源简历删除会连带清理其结果、评价、题目、报告和向量。

## 面试官

使用公司创建的面试官账号登录，进入“我的面试安排”。只能读取当前获分配候选人的必要资料和已有面试题。草稿仅本人可见；有排期时须到计划结束时间才能提交评价，提交后不能修改。排期取消/未到场或分配撤销会限制后续评价操作，页面提示为准。

面试建议与HR初筛、最终招聘结果分别保存；提交评价不会自动录用或淘汰候选人。

## 招聘支持

资料库上传岗位说明、制度和技术标准等参考资料，资料问答返回答案与来源。私人知识库、聊天不随岗位协作共享。内容审核是资料草稿工作流，不是招聘结果审批；达到拒绝上限不会强制批准。

## 检查与问题定位

- 无法加载页面数据：核对前端代理18080和Compose健康状态，确认登录及当前授权。
- 模型/向量调用失败：核对Python加载的DeepSeek/硅基流动配置及实际代理，不把hash模式当作真实向量验收。
- 表不存在或缺列：查看[迁移顺序](../../deploy/migrations/README.md)；已有卷不会自动更新表结构。
- 任务或评价版本冲突：保留当前输入，刷新核对最新状态；不要反复创建新付费任务。
- 自动检查：根目录运行`python scripts/verify-release.py`，见[统一验收](../acceptance/RELEASE_VERIFICATION.md)。
- 真实验收会创建专用测试公司并实际调用模型，见[真实验收记录](../acceptance/LIVE_RECRUITMENT_ACCEPTANCE.md)。

核心功能和单样本真实主流程已验收；外部通知、日历邀请、投递入口、Offer/入职管理未实现，生产部署、压测和备份恢复仍待验收。
